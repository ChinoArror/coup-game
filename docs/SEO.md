# Search indexing for Coup: Shadow Protocol

## Which URLs are public

The production canonical origin is `https://coup.aryuki.com` (`SITE_URL` in `wrangler.toml`). The Worker renders the public home page (`/`) and rules page (`/rules`) into the initial HTML response. These are the only indexable routes. The home page links to the rules with a normal anchor. The app, direct match, rooms, invitations, SSO callback, and administrative views are private or personalized and return `noindex` HTML.

`seo.tsx` is the public page registry. Register any future static public page there with a real title, description, locale, and render function; `/sitemap.xml` reads that same registry, so no separate sitemap edit is needed. There is currently no public D1 or CMS content. Room records and game history are private and must not be added to the sitemap. If a public database-backed content type is introduced, extend the sitemap source to query only published slugs and real modification timestamps. The sitemap currently omits `lastmod` because there is no reliable per-page date.

The Worker normalizes trailing slashes with a 308 redirect, omits tracking queries from canonical URLs, returns a real 404 for unknown paths, and redirects the production `workers.dev` hostname to the canonical origin. Cloudflare must also route any `www.coup.aryuki.com` hostname to this Worker or an equivalent redirect rule if that hostname is configured. The Worker cannot redirect a hostname whose DNS and route do not reach it.

`ENVIRONMENT=production` permits indexing on public pages. Any staging or preview deployment must explicitly set `ENVIRONMENT=preview` (or another non-production value); its HTML then carries `noindex,nofollow` and an `X-Robots-Tag`. Do not reuse the production `wrangler.toml` unchanged for a preview hostname. The production `workers.dev` hostname is redirected by the Worker.

HTML is generated by rendering the public React components at the edge and inserting them into the Vite asset shell. The interactive game remains a client-rendered app. This preserves the existing game architecture while giving crawlers and people the same initial public content. The public pages do not contain user data.

## Google Search Console

1. Add `aryuki.com` as a **Domain property** in [Google Search Console](https://search.google.com/search-console) and verify the DNS TXT record. DNS verification is preferred because it covers subdomains.
2. Submit `https://coup.aryuki.com/sitemap.xml` under Sitemaps.
3. For an important new public URL, use URL Inspection → Test Live URL → Request Indexing after deployment.

If URL-prefix HTML verification is preferred, set the Worker secret `GOOGLE_SITE_VERIFICATION` to the verification token. The Worker emits the corresponding meta tag on production public pages; never commit a real token. Google indexing is not guaranteed by a sitemap or an indexing request. The general Google Indexing API is not used.

## Checks

Build and start a local Worker to test the complete edge response:

```sh
npm run build
npx wrangler dev --local --port 8787
```

In another terminal, run `SEO_BASE_URL=http://127.0.0.1:8787 npm run check:seo` (PowerShell: `$env:SEO_BASE_URL='http://127.0.0.1:8787'; npm run check:seo`). Without `SEO_BASE_URL`, the script checks production. For a preview deployment, set `SEO_EXPECT_NOINDEX=1` as well. The script checks the raw HTTP HTML, robots, sitemap, 404, private noindex, and slash redirect. It does not test Search Console indexing decisions.
